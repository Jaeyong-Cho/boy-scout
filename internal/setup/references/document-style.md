# Document Writing Guidelines

When creating or editing documents, optimize for **accurate communication**, not elegant prose.

> Help the reader understand the subject quickly, make the correct judgment, and take the necessary action.

Each topic below is its own file under `document-style/`, loaded only when needed — read this index first, then open just the file the task calls for.

## Common Rule — MUST READ

**MUST** read `document-style/understanding-and-structure.md` for every document, no exceptions — it decides what goes in and in what order, before any situational file below applies.

**MUST** also read `document-style/frontmatter.md` for every document written under `~/wiki/**/*.md` or a target repo's `spec/**/*.md` — the OKF frontmatter block (`type`/`title`/`description`/`resource`/`tags`/`timestamp`) every such file carries. When reading or writing first-party source code, follow that file's language-safe metadata-header rule too.

## How To Use This Map

- Editing or tightening prose sentence by sentence: open `document-style/writing-rules.md`.
- Writing a bug report, README, design doc, meeting notes, work report, or making an argument/comparison: open `document-style/structures.md` for the matching template.
- Titling a document, adding examples, or trimming fluff: open `document-style/polish.md`.
- Before returning the final document: open `document-style/review-checklist.md`.
- Drawing a flow or structure diagram: open `document-style/ascii-diagram.md`.
